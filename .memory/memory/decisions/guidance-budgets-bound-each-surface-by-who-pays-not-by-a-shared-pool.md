Issue #4458 asked whether to re-arm the global total-guidance ratchet that #3745 retired. Decided in PR #4475 to leave it retired, and to cap the previously unmetered on-demand reference surface per file instead. `file_budgets` keys may now be globs, and `.agents/skills/act-as-mohab/references/**/*.md` is capped at 16384 bytes per file.

The rule worth keeping is that guidance budgets bound each surface by who pays when the ceiling binds, never by a shared pool. Under a per-file cap the file that grew is the file that pays, and its remedy is splitting, which genuinely lowers what a task loads. Under a pool the only way to fund one file's growth is deleting a neighbour's prose, which lowers nothing any session actually loads, because that neighbour was never in it. The empirical half matches the argument. The per-surface caps from #3745 have never been renegotiated, while the pooled floor was renegotiated three times in one week, from 68 to 55 to 53 percent, and at one point forced deleting good prose over 21 bytes.

One correction, because a future reader will otherwise over-claim this. A per-file cap does not bound a session total. Routing in this repository loads several references per task, and `references/routing.md` lines 12 to 16 send every dispatch through both `delegation.md` and `roles.md`, so a realistic dispatch loads roughly 28639 bytes, about 1.75 times the per-file cap. An earlier draft of this rationale claimed routing sends a task to a single reference, and review caught it as false. The decision stands on the who-pays argument alone, not on any claim that one task loads one file.
