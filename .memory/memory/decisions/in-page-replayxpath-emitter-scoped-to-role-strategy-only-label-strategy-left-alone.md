Issue #4026 (self-verified in-page XPath emitter) was implemented in shaft-capture-recorder.js for ROLE-strategy candidates only: computeReplayXpath keys the predicate to the DOM signal that produced the accessible name (aria-label/alt/title/element-own-text via normalize-space()), self-verified with document.evaluate before being recorded. LABEL-strategy candidates get their name from a DIFFERENT DOM node (an associated <label> element via .labels or a wrapping <label>), so a self-verified XPath rooted at the target element's own tag/attributes/text cannot express that cross-element association cleanly. Left LABEL-strategy replayXpath unimplemented (blank, same as before) rather than guessing; CaptureGenerator's existing .containsText(...) fallback still handles it. Flagged as a possible follow-up in PR #4052, not filed as a separate issue since it is not a regression.
