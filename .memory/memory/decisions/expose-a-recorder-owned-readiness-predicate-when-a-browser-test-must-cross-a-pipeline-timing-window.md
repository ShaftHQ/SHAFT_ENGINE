Issue #4508: ManagedCaptureRecorderBrowserTest.backForwardJourneyRecordsUserTraversals used fixed sleeps to outlast CaptureEventPipeline's two-second overlay identity attach window. A 50 ms dwell deterministically lost the Back traversal in both Chrome and Edge. The test now waits on recorder.readyForDistinctUserTraversal(), backed by the pipeline's last appended navigation timestamp, then waits for the exact Back and Forward row counts. This keeps timing ownership with the recorder and turns delayed delivery into a bounded condition timeout.
