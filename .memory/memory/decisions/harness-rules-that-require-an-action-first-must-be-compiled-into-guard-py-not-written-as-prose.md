Every rule guard.py compiles today (R1 Maven scoping, R2 Allure serve, R3 GUI verbs, R8 git stash, R9 worktree add, R10 memory write from a linked worktree) blocks a bad action. Not one requires a good action first. The harness has therefore deterministically enforced exactly the class of rule that survives on its own, and left every 'always do X before Y' rule -- retrieval before discovery (#4540), check-in cadence (#4530), state on the issue (#4536), draft PR and push cadence (#4538) -- as prose.

Two 2026 results say that is the wrong way round. arXiv 2604.20911 measures that one constraint class decays as context grows while the other persists, and that restating, templating or detecting the rule recovers only ~50-70% compliance at realistic context lengths. arXiv 2607.25398 (HANDBOOK.md) benchmarks this harness's exact shape -- a long binding policy document, 824 deterministic criteria -- and the best frontier model passes 36.2% under strict grading, most below 25%; agents typically do the work and miss the controls. Its four failure patterns are all observed here: verification skipped, checks performed then ignored, environmental override, and false compliance reporting ('the agent's self-report is the least reliable artifact in the trajectory').

Two consequences that rule out the tempting fixes. Failures persist at maximum reasoning effort and sometimes worsen, so a stronger adjective, more deliberation, or a higher capability level does not address this class -- extra thinking helps a missed inference, not a missed read. And the paper's own recommendation is to enforce hard controls outside the model by compiling policy into deterministic tool-call guards, which matches Anthropic's guidance that CLAUDE.md instructions are advisory while hooks are deterministic and guarantee the action happens.

Decision: #4530, #4536, #4538 and #4540 are not four rules each needing its own enforceable-or-boilerplate verdict. They are one architectural gap. The question the group owes is whether guard.py grows a required-before rule class; once it has one, all four are instances of it. Strongest form is to remove the need to remember at all -- have the SessionStart hook perform the always-relevant retrieval and inject the result -- with a PreToolUse required-before guard as the fallback for what cannot be pre-supplied, and depth scaled to the blast radius triage already computes so the guard is not a tax on trivial work.

Evidence this is real rather than theoretical: the session that produced this record loaded the entrypoint, ran triage, then went straight to gh issue list, git ls-files and rg without querying any store, and reported done. The owner caught it; no check did. When the stores were finally queried, MemPalace returned in one call that an earlier entrypoint carried these triggers inline as an enforced section, and .memory already held constraint.memory-and-graphify-are-a-mandatory-session-entry-point.
