dorny/paths-filter cannot resolve a diff base outside push/pull_request events, so pr-gate.yml is deliberately pull_request-only (a workflow_dispatch run would fail the changes job or pass vacuously). GitHub applies an implicit success() to dependent jobs whose if-condition lacks a status function: if the changes job is skipped, every leg is skipped and a naive summary goes green having tested nothing. The summary job must explicitly fail unless needs.changes.result == 'success' (fail-closed). Required check context on main: 'PR Gate Summary' (ruleset id 19182579).

Third trap (#4478, PR #4499): a leg's path filter IS part of the check that runs in it. A test can exist, be correct, run in CI, and still never run for the edit it guards -- if the file it guards is listed only in a DIFFERENT leg's filter. Concrete case: tests/scripts/test_install_shaft_mcp.py::test_marketplace_lists_every_canonical_skill_directory asserts .claude-plugin/marketplace.json equals sorted(shaft-skills/*/SKILL.md), but runs in the installer-verify leg, gated by the `intellij` filter, which lists shaft-skills/** and NOT the manifest. So renaming a skill directory was caught, while editing the manifest alone (the actual hand-edit drift) triggered only the agent-guidance leg, which never ran that test -- zero checks. Fixed by moving the assertion into scripts/ci/validate_skills.py, which validate_agent_setup.py imports and the agent-guidance leg runs, and whose filter already lists both inputs. When adding or auditing a gate, verify the filter that triggers it lists every input it reads, not just the one that motivated it.
