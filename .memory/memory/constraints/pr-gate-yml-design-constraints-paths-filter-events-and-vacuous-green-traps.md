dorny/paths-filter cannot resolve a diff base outside push/pull_request events, so pr-gate.yml is deliberately pull_request-only (a workflow_dispatch run would fail the changes job or pass vacuously). GitHub applies an implicit success() to dependent jobs whose if-condition lacks a status function: if the changes job is skipped, every leg is skipped and a naive summary goes green having tested nothing. The summary job must explicitly fail unless needs.changes.result == 'success' (fail-closed). Required check context on main: 'PR Gate Summary' (ruleset id 19182579).

Third trap (#4478, PR #4499): a leg's path filter IS part of the check that runs in it. A test can exist, be correct, run in CI, and still never run for the edit it guards -- if the file it guards is listed only in a DIFFERENT leg's filter. Concrete case: tests/scripts/test_install_shaft_mcp.py::test_marketplace_lists_every_canonical_skill_directory asserts .claude-plugin/marketplace.json equals sorted(shaft-skills/*/SKILL.md), but runs in the installer-verify leg, gated by the `intellij` filter, which lists shaft-skills/** and NOT the manifest. So renaming a skill directory was caught, while editing the manifest alone (the actual hand-edit drift) triggered only the agent-guidance leg, which never ran that test -- zero checks. When adding or auditing a gate, verify the filter that triggers it lists every input it reads, not just the one that motivated it.

The fix DUPLICATED that assertion into tests/scripts/test_validate_skills.py; it did not move it. test_install_shaft_mcp.py:553 is untouched, so one invariant now has two implementations, justified only because they have different pr-gate triggers. They order differently and will disagree the moment a skill name is not all-lowercase: the installer test sorts Path objects (case-insensitive on Windows, case-sensitive on POSIX), the newer one sorts strings (neither). Latent, not live, at 30 lowercase names.

Putting the manifest check there made the installed validate_agent_setup.py -- the aggregate two playbooks tell agents to run -- exit 1 with `marketplace-missing` for every onboarded user; measured pre/post on a scaffolded project (exit 0 -> exit 1). Nothing on that PR could have caught it: test_install_shaft_mcp.py guards only module IMPORTS travelling with the manifest, and validate_skills.py is in the agent_guidance filter but not the intellij filter, so Installer verification was SKIPPED on the run that introduced it. Before adding a check to anything under scripts/ci/, confirm it is not in AGENT_VALIDATION_SCRIPT_FILES; repo-only invariants belong in tests/, which never ship.
