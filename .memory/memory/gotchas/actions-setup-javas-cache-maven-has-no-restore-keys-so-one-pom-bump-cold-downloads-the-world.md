actions/setup-java passes no restoreKeys to cache.restoreCache -- deliberately, per its own src/cache.ts comment: "No 'restoreKeys' is set, to start with a clear cache after dependency update". Its key is an exact hash of every pom.xml, so any Dependabot BOM bump discards the whole ~500 MiB ~/.m2/repository and the next run logs 'maven cache is not found' with no fallback.

That is survivable for a single-job build and fatal for a fan-out one. e2eTests.yml starts 22 jobs through .github/actions/setup-test-env; on 2026-08-04 (run 30876948089, job 91890245030) three pom-touching commits (#4415, #4416, #4419) had landed since the passing 08-03 nightly, so all 22 jobs cold-resolved the reactor from repo.maven.apache.org within the same few seconds and Central answered 'status code: 429, reason phrase: Too Many Requests' for every BOM after ~6 minutes of resolver retries. 'Install optional visual test runtime' carries no continue-on-error (the 'Run tests' step directly below it does), so the job stopped there, 'Run tests' was skipped, and 'Post-Test Report and Check' then failed on 'No Allure summary was generated'. The 429 is the visible error; the cache miss is the cause.

Exact-key caching also loses the entry to LRU: it is only touched on runs whose pom hash happens to match, and repo cache usage was 9.08 of 10 GiB (multi-GiB Gradle entries dominate), so 08-03's Maven cache had already been evicted. A restore-key prefix fixes both -- delta-only downloads and an entry touched every run.

Fix (PR #4443): .github/actions/cache-maven-repo, key shaft-m2-<os>-<arch>-<pom-hash> with restore-key prefix shaft-m2-<os>-<arch>-. Keep that key format identical at every call site; two formats mean two ~500 MiB cache families per pom hash, which the eviction budget cannot afford.

The action also deletes *.lastUpdated after restore. Maven records failed release resolutions there and, with the default 'never' update policy for releases, will not reattempt them -- a failure mode only reachable once restore-keys exist, because without them a poisoned cache could never be restored at all.
