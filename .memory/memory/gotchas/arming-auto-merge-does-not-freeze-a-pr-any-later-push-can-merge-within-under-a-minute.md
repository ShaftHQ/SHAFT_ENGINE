The actual, evidence-backed hazard: once auto-merge is armed, it is not a snapshot of the commits that existed at arm-time -- it re-evaluates and can fire within under a minute of ANY subsequent push (a fix, an amend, a rebase), leaving no realistic window to catch a problem in that push (e.g. re-reading a commit message) before it reaches `main`. Safe sequence: disarm auto-merge first (`gh pr merge --disable-auto`), make the edit/push, verify the new head's content (`git log <base>..HEAD --format=%B`, per the existing squash-commit-message gotcha), THEN re-arm auto-merge.
