A child module's own <dependencyManagement> outranks both the parent POM's management and any direct pin declared in a sibling module; among multiple BOMs imported into that same child block, the first import wins. shaft-mcp/pom.xml imports spring-boot-dependencies into its own dependencyManagement, and this has silently downgraded already-patched versions three times, always without a build failure or warning -- the wrong version just resolves: (1) selenium -- shaft-mcp/pom.xml:43-46 documents importing selenium-bom before spring-boot-dependencies, because Spring Boot manages org.seleniumhq.selenium at an older version and would otherwise win; (2) netty -- root pom.xml:77 pins netty.version=4.2.16.Final and pom.xml:274-280 imports netty-bom, but shaft-mcp resolved 4.2.15.Final from spring-boot-dependencies:4.1.0 until fixed, causing 11 open Dependabot alerts #155-#165; (3) postgresql -- shaft-engine/pom.xml:469-472 declares org.postgresql:postgresql:42.7.13 directly, but shaft-mcp resolved 42.7.11 from the same Boot BOM, causing Dependabot alert #154 (PR #4019 fixes netty and postgresql the same way selenium was already fixed). Fix pattern: import the corrective BOM before spring-boot-dependencies in shaft-mcp's own dependencyManagement (first import wins), or add a direct managed-dependency entry (direct entries outrank imported BOMs) -- shaft-mcp/pom.xml:33-42 already does this for logback-classic/logback-core for the same reason. How to apply: whenever a version pin set elsewhere in the reactor appears not to take effect inside shaft-mcp, check shaft-mcp/pom.xml's dependencyManagement ordering FIRST, and verify the actually-resolved version with `mvn -pl shaft-mcp dependency:tree -Dincludes=<groupId>` (no -am) rather than trusting the pin. Related but distinct: gotcha.appium-java-client-hard-selenium-version-ranges-beat-bom-pins covers hard version RANGES in a transitive dependency (e.g. Appium java-client) beating pins via live Maven Central metadata resolution (MNG-4463) -- a declaration-order/precedence issue here, not a live-resolution one there, though both surface as 'my pin didn't take effect'.
