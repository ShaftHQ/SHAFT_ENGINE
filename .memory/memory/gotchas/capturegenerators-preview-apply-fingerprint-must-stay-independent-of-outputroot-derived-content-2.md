CaptureGenerator.generate() SHA-256-fingerprints a 'deterministic source' render to detect drift between a control-flow/enrichment PREVIEW and its later APPLY (CaptureGeneratorTest#approvedControlFlowPreviewGeneratesOptionalGuard/#approvedEnrichmentIsAppliedThenRecompiled deliberately call PREVIEW and APPLY against DIFFERENT output directories -- intentional, not an oversight). Issue #4172 embedded an absolute, outputRoot-derived healing.history.path into that same rendered source, which broke both tests: the fingerprint computed at PREVIEW time (from outputRoot A) no longer matched the one recomputed at APPLY time (from outputRoot B), because that ONE line differed. Fix: render the fingerprint-only 'deterministicSource' with a stable placeholder path (CaptureGenerator.FINGERPRINT_HEALING_HISTORY_PATH) instead of the real per-call absolute path; only the FINAL written source uses the true healingHistoryPath. Anyone adding another outputRoot-dependent line to generated source must apply the same placeholder-for-fingerprinting treatment or repeat this regression.
