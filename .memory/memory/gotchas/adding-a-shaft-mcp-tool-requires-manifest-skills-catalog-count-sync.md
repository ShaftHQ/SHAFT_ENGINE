Adding or removing a shaft-mcp `@Tool(name=...)` trips pr-gate.yml's installer-verify job's 'Run unittest for installer script' step (python -m unittest tests.scripts.test_install_shaft_mcp tests.scripts.test_generate_shaft_skills_tool_catalog tests.scripts.test_mcp_tool_catalog_sync) on all OS. In the SAME PR you must: (1) add a {name,mutation,sensitive,deprecated} entry per tool to shaft-mcp/src/test/resources/fixtures/mcp-tool-manifest.json (omit intentKeywords unless also added to the assistant command table); (2) regenerate shaft-skills/references/shaft-mcp-tools.md via `py -3 scripts/mcp/generate_shaft_skills_tool_catalog.py`; (3) bump the expected count in tests/scripts/test_generate_shaft_skills_tool_catalog.py (assertEqual(<N>, total)). Verify locally: the 3 tests.scripts unittests + scripts/ci/validate_shaft_mcp_configuration.py + scripts/ci/validate_installer_contract.py. Only pr-gate.yml's installer-verification leg (installer-verify job) gates this, not the engine Maven build-and-verify.

Never hand-edit shaft-mcp-tools.md directly -- a hand-edit that misses the 'Total tools: N' header passes local Java tests but fails installer-verification on all 3 OS (evidence: PR #3582, mobile_api_record_transactions, count 164->165). Adding only a PARAMETER to an existing tool (no name/description/count change) trips none of this. First discovered missing twice in PRs #3454/#3459 and hotfixed in #3460, before this full procedure was written up.
