Three Windows-only LF/CRLF mismatch failure modes. (1) MAX_PATH checkout failure: an overlong `.memory/relations/` filename makes `git checkout` itself fail on windows-2025 runners (and plain `git clone` for users without `core.longpaths`). Mitigated by 'Enable Windows long paths' steps before checkout in all Windows-capable workflows; durable fix (#3438): `scripts/ci/validate_agent_setup.py` fails any `.memory/{memory,relations}` basename over 160 chars (`memory-filename-length` code). (2) autocrlf vs CI generator byte-compare drift gates: Windows runners materialize committed text with CRLF; any generator `--check` comparing bytes against LF output reports false drift on Windows CI only, while local runs pass (freshly generator-written, never checkout-round-tripped). Fix pattern: normalize CRLF->LF in the comparison AND pin `eol=lf` in `.gitattributes`. (3) Hand-measured guidance byte deltas: measuring a guidance file's byte delta by comparing `git show` (LF) against `pathlib.Path(f).read_bytes()` (CRLF on Windows) silently violates LF-normalization and produces wrong results. Observed in PR #4479: this method reported +146 for `.agents/skills/act-as-mohab/SKILL.md`, which had actually lost 80 characters (validator's `always_loaded_body_chars` moved from 15596 to 15516). The two metrics disagreed by 226 bytes—the file's line count—plausible enough to look like measurement noise rather than an artifact. Fix: use the validator's native `guidance_bytes` metrics (via `py -3 scripts/ci/validate_agent_setup.py --skip-external --format json`), or decode and normalize both sides (`replace("\r\n", "\n")`) before comparing. How to apply: (1) make any generated-file drift gate EOL-insensitive from day one and add the output path to `.gitattributes`; (2) when a Windows CI job dies in <20s, suspect checkout itself; (3) never compare `git show` bytes against `read_bytes()` on Windows for measurement; (4) when a Memory object/relation id needs shortening, prefer structured patch (`memory patch review`/`memory save --file`, then `memory check`) over hand-editing JSON+filename.
