ManagedCaptureRecorderBrowserTest carries a class-level @Tag("external-e2e") (ManagedCaptureRecorderBrowserTest.java:43), but that tag is not sufficient gating on its own: .github/actions/capture-browser-e2e/action.yml runs this exact class by name (-Dtest=ManagedCaptureRecorderBrowserTest,CaptureGeneratedReplayBrowserTest) with -DincludeCaptureBrowserE2E, bypassing whatever the tag would otherwise exclude. That composite action is wired into pr-gate.yml (PR-blocking, .github/workflows/pr-gate.yml:243), mavenCentral_cd.yml, and shaft-pilot-release.yml. A hanging or expensive test in that class would hang every PR's gate regardless of its @Tag. Confirmed in PR #4068 (Refs #4046), which had to add an explicit @Disabled on the hanging method rather than rely on the tag. Rule: to keep a test out of CI, verify how the calling action actually selects tests (by tag, by name, by profile) -- do not assume a tag alone is a gate.
