RESOLVED by issue #4341: ElementActionsHelper.failAction (the failure path used by TouchActions gestures like tap/doubleTap/longTap/swipe/rotate, plus ElementActions' table-locator lookup, AlertActions, and BrowserActions' mobile-context methods) used to route through Assertions.fail, throwing AssertionError -- unlike Actions.performAction's reportBroken path, which throws RuntimeException for the equivalent browser-action failure. Fix: failAction now throws new RuntimeException(message, rootCauseException[0]), preserving the full cause chain -- every failAction call site is a broken/failed-action report, never a genuine assertion. Whole-engine + every shaft-*module's src/main audited for Assertions.fail(/Assert.fail(/throw new AssertionError/AssertionFailedError: the only other hits (ValidationsHelper hard-assert, RequestBuilder status-code check, AccessibilityActions violation/score checks, HttpContractRecorder ASSERT-mode diff, FailureReporter's dedicated failAssertion) are genuine expected-vs-actual assertions, untouched. Fallout fixed in the same PR (#4344): TouchMultipleElementsFailureTest and BrowserActionsCoverageUnitTest assertions tightened from Throwable/AssertionError to RuntimeException; TouchActions.swipeElementIntoView's inner catch changed from catching AssertionError to RuntimeException (was silently redundantly re-wrapping an already-reported failure an extra time -- caught via a new mocked-overload-count regression test). IMPORTANT PROCESS GOTCHA: a `grep -rn "catch (AssertionError"` sweep across src/test was done and most hits were correctly triaged as genuine-Validations-test noise by spot-checking a few representative ones -- but FailureTraceReporterTest.java:417 (touchTraceShouldIncludeMobileFailureMetadata, asserting on TouchActions.rotate's failure path) was skipped over and only caught by CI's full 1561-test suite run, not the scoped local regression pass. Lesson: when a fix changes a widely-shared method's exception type, every `catch (AssertionError` / `assertThrows(AssertionError` hit touching that method's call chain must be individually verified against the call chain (which concrete action method feeds into it), not sampled -- and a scoped local -Dtest pass is not a substitute for letting CI's full-suite run be the completeness gate before merge.
