ElementActionsHelper.failAction (the failure path used by TouchActions gestures like tap/doubleTap/longTap/swipe) routes through Assertions.fail, which throws AssertionError. This differs from Actions.performAction's reportBroken path, which throws RuntimeException for the equivalent browser-action failure. Consequence: test/calling code written to catch or assert on RuntimeException (the pattern used throughout MultipleElementsFailureTest and similar) will NOT catch an equivalent TouchActions failure -- it needs a Throwable/AssertionError-aware catch instead. Confirmed while adding TouchMultipleElementsFailureTest (issue #4332, PR #4340), which had to assert on Throwable unlike MultipleElementsFailureTest's RuntimeException-typed assertions. Tracked as issue #4341 for a possible unification decision -- not yet resolved as of this writing.
