On Windows, Python os.kill(pid, 0) is not a POSIX-style existence check: it can terminate the target process. In the learning-loop concurrency test this killed the Python/Codex tool host, closed stdout, and made each resume appear to crash. Use an OS-held file lock for serialization, or a documented Windows process-query API when liveness is truly required. Evidence: PR #4729, commit 88bb491d41, and the 12-process record_signal regression in tests/scripts/test_learning_signal_ledger.py.
