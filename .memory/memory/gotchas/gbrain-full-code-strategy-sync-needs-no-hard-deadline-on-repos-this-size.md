`gbrain sync --strategy code --full` on SHAFT_ENGINE (1660 code files) hit the CLI's own default 1-hour hard-deadline watchdog before finishing (SIGTERM at 47%/790 files, exit code 1) -- local Ollama embedding of larger Java/JSON files can take 5-76s each. This is not a crash; the CLI logs a sync-watchdog line stating the deadline was reached and it is sending SIGTERM for graceful shutdown. Re-running the same sync command picks up cleanly via the sync's own file-level checkpoint (logs report resuming and skipping already-processed files) -- no data loss, no re-embedding of already-done files. For a full first-time code-strategy sync on a repo this size, pass --no-hard-deadline (or expect to resume once or twice) rather than treating a killed/exit-1 run as a real failure.
