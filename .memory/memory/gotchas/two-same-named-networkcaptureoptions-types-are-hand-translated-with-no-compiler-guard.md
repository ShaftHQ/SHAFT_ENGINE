shaft-capture has two distinct types sharing the simple name NetworkCaptureOptions: com.shaft.capture.runtime.NetworkCaptureOptions (mutable, Spring-AI-bound from MCP JSON) and com.shaft.capture.network.NetworkCaptureOptions (normalized record). They are bridged by ManagedCaptureRecorder.translateNetworkCaptureOptions (ManagedCaptureRecorder.java:1050-1060), a hand-written mapping with no compiler guard: fields absent from the mapping vanish silently, and the excludeAssets<->includeAssetTypes polarity flip is a bare `!options.excludeAssets` (line 1053) that is easy to get backwards. Two separate defects came out of this one seam: #4014 (the polarity inversion itself, fixed by commit 5cd02119ca / PR #4056) and #4057 (enabled/captureRequestBodies/captureResponseBodies silently dropped instead of carried through, fixed by commit 55263b2792 / PR #4064). Rule: any field added to either NetworkCaptureOptions type must be checked by hand against this translation method -- there is no compiler error if a field is forgotten.
