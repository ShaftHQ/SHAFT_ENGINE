Two separate traps when creating a worktree on Windows (filed as #4126). (a) `git worktree add` with a backslash Windows path run through the Bash tool (Git Bash/MSYS) silently creates a garbage single-segment directory at the repo root -- Bash eats the backslashes as escapes. Exit code 0, no error surfaced. Fix: always use forward slashes, e.g. `git worktree add C:/Users/.../repo/.claude/worktrees/<name> -b <branch> origin/main`. (b) Plain `git worktree add` aborts with `Filename too long` on `.memory/**` paths (Windows MAX_PATH). Fix: per-invocation `git -c core.longpaths=true worktree add ...` -- never a persistent config change.
Same root cause as the closed MAX_PATH incidents (see [[memory-cli-supersede-shorthand-fails-on-windows-with-long-object-ids]], [[windows-ci-max-path-checkout-failure-autocrlf-byte-compare-drift]]) and the open #4110, but it bites at worktree-creation time, blocking an agent before it even starts.
