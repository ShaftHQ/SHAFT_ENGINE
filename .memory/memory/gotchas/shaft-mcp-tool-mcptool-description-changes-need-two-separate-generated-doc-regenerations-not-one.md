Editing a CaptureService @Tool/@McpTool description or adding @ToolParam/@McpToolParam only satisfies the shaft-mcp Maven drift gate (ToolIndexMechanicalDumpTest -Dshaft.toolIndex.write=true regenerates tool-index-mechanical.json, then `python3 scripts/mcp/generate_tool_index.py` regenerates the merged tool-index.json). A SEPARATE, unrelated-looking generator also drifts: `python3 scripts/mcp/generate_shaft_skills_tool_catalog.py` regenerates shaft-skills/references/shaft-mcp-tools.md straight from the Java source via its own regex/static parse of @Tool descriptions. Neither `mvn -pl shaft-mcp test` nor the tool-index Python check catches the second drift -- only CI's 'Installer verification' job (python -m unittest tests.scripts.test_generate_shaft_skills_tool_catalog, specifically test_check_mode_passes_against_committed_catalog) does. Confirmed live on PR #4243: local shaft-mcp Maven suite (75 tests) plus generate_tool_index.py --check were both green, but CI's Installer verification job still failed until shaft-mcp-tools.md was separately regenerated and pushed. Any future change to a CaptureService (or other shaft-mcp service) @Tool/@McpTool description must run both generators before pushing: (1) mvn -pl shaft-mcp test -Dtest=ToolIndexMechanicalDumpTest -Dshaft.toolIndex.write=true && python3 scripts/mcp/generate_tool_index.py, and (2) python3 scripts/mcp/generate_shaft_skills_tool_catalog.py.
