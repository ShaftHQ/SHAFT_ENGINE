Decompiling com.intellij.openapi.application.ApplicationManager.class (IntelliJ Platform, ideaIU-2024.3) shows the 2-arg setApplication(Application, Disposable) overload registers a Disposer callback shaped like `previous -> { if (previous != null) setApplication(previous); }`. In shaft-intellij's Gradle unit-test JVM, ApplicationManager.getApplication() is normally null (no real IDE Application exists), so `previous` captured at install time is null, and the restore-on-dispose callback is a silent no-op -- Disposer.dispose(disposable) alone never nulls ApplicationManager.ourApplication back out. This leaked a fake Proxy Application installed by two new AssistantTranscriptViewTest tests (PR #4238, issue #4233's own regression coverage) as the JVM-wide ApplicationManager singleton for the rest of the Gradle test fork, causing 219/1218 shaft-intellij tests to fail in CI across totally unrelated classes (first hit: LookAndFeelIsolationExtensionTest, because DarculaLaf.getDefaults() -> ClientSystemInfo.isMac() -> ClientSessionsManager.getAppSession() called getService() on the leaked all-null-returning proxy and threw IllegalStateException, logged as ERROR and converted to a TestLoggerFactory$TestLoggerAssertionError -- and every other test gated on "does a live Application exist" (the standard guard throughout this codebase) cascaded the same way for whatever ran afterward in the same fork). Fix: after Disposer.dispose(disposable), explicitly call ApplicationManager.setApplication(null) too -- never rely on the disposer-based restore alone when the previous Application was/may be null. shaft-intellij/src/test/java/com/shaft/intellij/ui/LiveChatToolE2ESupport.java:57-64 has a pre-existing, incorrect class-level javadoc claiming this restore is unconditional/"fully reversible"; it has the same latent leak in its own setApplication(fakeApplication, applicationDisposable) call (LiveChatToolE2ESupport.java:133), currently masked only because every caller is gated behind live-only test flags (-Dshaft.intellij.liveToolE2E=true etc.) that skip the test bodies in normal PR-gate CI. Filed as issue #4242, not fixed (out of scope for #4233/#4238).
