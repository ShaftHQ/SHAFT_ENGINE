Issue #4105, fixed in PR #4109 (commit 6bbe4f3a95). .github/actions/post-test-report/action.yml's step keeps `set -euo pipefail` for its whole body; the RESULT_COUNT line ran `find "$ALLURE_RESULTS_DIR" -name '*-result.json' -type f 2>/dev/null | wc -l`. GNU find returns exit status 1 when the given start path does not exist at all (distinct from matching zero files, which is exit 0 with empty output) -- with pipefail active that nonzero propagates through the pipe and errexit kills the whole script before it ever reaches the action's own clean ::error:: diagnostic, so a missing allure-results directory produced total silence instead of an actionable message. Fix: guard with `if [ -d "$ALLURE_RESULTS_DIR" ]; then RESULT_COUNT=$(find ...); else RESULT_COUNT=0; fi` (post-test-report/action.yml, RESULT_COUNT block) -- verified locally with a before/after repro against a confirmed-absent directory (pre-fix: silent exit 1, no output; post-fix: reaches the intended ::error:: message). General rule: any `find <path> | ...` under pipefail needs a `[ -d <path> ]` (or equivalent existence check) first if <path> can legitimately be absent, not just empty.
