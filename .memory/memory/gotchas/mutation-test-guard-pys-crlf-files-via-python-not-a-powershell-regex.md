scripts/agents/guard.py is CRLF-terminated (verified: 2019 CRLF line endings, 0 bare LF). A PowerShell here-string regex substitution used to delete or corrupt a predicate for a required mutation test can fail to match across CRLF line endings and silently leave the file byte-for-byte unchanged. The self-test then still reports the mutated-away assertions as passing -- not because the predicate survived, but because it was never actually removed -- which reads exactly like a successful mutation-kills-the-test result while proving nothing. Verify the mutation actually landed before trusting its outcome: `git diff --stat <file>` must show the expected deletion, and/or `grep` for the removed symbol/call-site must return nothing. Prefer a small Python script that opens the file with `encoding='utf-8', newline=''` (round-trips CRLF unchanged) to apply and later `git checkout -- <file>` to revert, rather than an in-place PowerShell regex edit on a CRLF file. Confirmed in PR #4517 (issue #4496): removed check_r9_worktree_add's branch-prefix predicate via a Python script, confirmed the 12-line removal via `git diff --stat` and a `grep` miss for the removed call site, then reran `--self-test` and saw the expected 3 assertion failures before restoring with `git checkout --`.
