The agent harness Bash tool keeps the working directory from the previous call ('Shell cwd was reset' notes are not guaranteed). In a session juggling multiple git worktrees this caused two real mistakes on 2026-07-18: a branch was created in an agent worktree instead of the main tree, and a memory commit landed on the wrong branch (grid-cdp-comment instead of guidance-budget-redesign), requiring a reset --hard + cherry-pick repair. Rule: every Bash call that depends on repo location starts with an explicit `cd <absolute path> &&`, especially git branch/commit/push operations.

Hit again 2026-07-21 from the orchestrator/main-thread side: a read-only `cd <delegate-worktree> && git log` left that cwd persisted, so a LATER release-branch `git checkout` + `git merge` + `git push` executed INSIDE the delegate's worktree, switching the delegate's HEAD mid-task (its uncommitted WIP survived but landed on the wrong branch); the orchestrator initially misattributed the collision to the delegate. Stronger rule when orchestrating/inspecting another agent's worktree: NEVER bare-`cd` into it, even read-only -- inspect with `git -C <worktree-path> ...` instead (stateless, does not touch the tool's persisted cwd), and before any state-changing git command verify `pwd` and `git rev-parse --show-toplevel` point at the intended checkout.
