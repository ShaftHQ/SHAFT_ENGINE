Extends the stage-by-exact-path rule (see concurrent-agents-in-shared-checkout-must-stage-by-exact-path-never-a-or): in a single non-worktree checkout shared by parallel agents, any agent's `git checkout` switches HEAD for everyone -- another agent's later commit then lands on the WRONG branch/PR. Observed twice on 2026-07-21 (T4's commit landed on the sweep branch; the CI-fix coder nearly committed onto the selector branch). Rules: (1) immediately before every commit, re-verify `git branch --show-current` and the expected tip; (2) prefer `git worktree add` isolation for any agent that can run concurrently with another; (3) never stash/reset another agent's uncommitted files -- hide them from a rebase's clean-tree check with `git update-index --skip-worktree <paths>` and unset afterwards. Inverse case, single agent (2026-07-26, issue #4103): even when an agent IS assigned its own worktree, its Bash tool does not necessarily start there -- one delegate's first `git checkout -b` ran inside the shared main checkout (C:\Users\Mohab\IdeaProjects\SHAFT_ENGINE) and briefly switched HEAD there before the agent caught it. No damage that time, but it is the same underlying risk as the multi-agent case above, just triggered by one agent's own unverified starting cwd rather than a sibling agent. Rule (4): a delegate's literal first action of a session, before any other git command, is `pwd` plus `git worktree list` to confirm the shell is inside the assigned worktree path, not the shared checkout.
