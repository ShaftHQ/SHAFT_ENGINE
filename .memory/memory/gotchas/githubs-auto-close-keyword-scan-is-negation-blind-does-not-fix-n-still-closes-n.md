Issue #3930 was manually reopened again afterward and is OPEN as of this writing (`gh issue view 3930 --json state`).

The scanner is quote-blind, not just negation-blind: it does not distinguish 'the text that follows is a real directive' from 'the text that follows is quoted prose describing a past incident.' Both failure shapes are the same dumb substring/keyword-adjacency match with zero semantic awareness of surrounding context (negation, quotation, meta-reference). The only safe way to mention an issue you are NOT closing, anywhere in a PR body or any commit that will reach the branch (including commits only quoting the phrase for documentation purposes), is a bare `#N` with no keyword (fix/fixes/close/closes/resolve/resolves) anywhere before it on the same line/sentence -- not even inside a negation, and not even inside quotation marks. `gh pr view --json closingIssuesReferences` being empty is not proof the eventual squash text is safe: it reflects the PR's head at query time, not necessarily the final squash-merge commit body GitHub actually scans at merge time.
