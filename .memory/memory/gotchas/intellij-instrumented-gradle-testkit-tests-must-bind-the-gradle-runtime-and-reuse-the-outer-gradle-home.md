In shaft-intellij tests, IntelliJ instrumentation relocates gradle-test-kit into the plugin test sandbox, so GradleRunner cannot infer a Gradle installation from its own JAR. Call withGradleVersion using the checked-in wrapper version. Also bind withTestKitDir to the outer build's gradle.gradleUserHomeDir (passed as a test system property) so the nested build reuses the already-resolved IntelliJ distribution instead of duplicating a multi-gigabyte cache in the default user home. When the nested contract depends on build.gradle.kts, declare that script as an input of the outer test task; otherwise Gradle may mark the JUnit test up-to-date after an omission mutation.
