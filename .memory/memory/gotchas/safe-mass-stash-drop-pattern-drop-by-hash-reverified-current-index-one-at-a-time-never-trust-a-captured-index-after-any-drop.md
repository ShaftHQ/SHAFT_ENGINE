git stash indices are positional and shift on every drop/pop; this repo already lost a stash once from an index-shift race (issue #4130 / R8 guard). To bulk-drop N target stashes safely: first capture each target's stable commit hash via git rev-parse stash@{i} (read-only, before any mutation). Then, immediately before each drop, re-scan the live stash list fresh and find that hash's CURRENT index -- never reuse an index captured earlier or computed in parallel. Never run concurrent/parallel drops against the shared stash list. This let 19 stashes get dropped sequentially with zero misapplied drops, confirmed because each target was found at index 0 (expected: processing in original list order means each next target shifts to the front after the prior removal).
