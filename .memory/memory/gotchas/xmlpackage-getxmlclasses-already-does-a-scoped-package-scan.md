org.testng.xml.XmlPackage.getXmlClasses() lazily calls org.testng.internal.PackageUtils.findClassesInPackage(name, include, exclude) and memoizes the result -- TestNG itself uses this to resolve <packages> at suite-build time. ProjectStructureManager.identifyRunType(List<XmlSuite>) (shaft-engine/src/main/java/com/shaft/tools/io/internal/ProjectStructureManager.java) reuses it directly instead of hand-rolling a classpath scanner to detect a Cucumber TestNG runner declared via <packages>. XmlClass.getSupportClass() also resolves lazily via ClassHelper.forName regardless of any <methods> include/exclude filter, so a runner class restricted by <methods> was never actually undetectable -- verified with a passing test before any fix (testPackage.unitTests.ProjectStructureManagerTest.identifyRunTypeWithSuitesDetectsCucumberTestNgRunnerClassFilteredByMethods). Child suites reached via <suite-file> show up at runtime as XmlSuite.getChildSuites(), not in the parent's getTests(); flatten with an identity-based visited Set (Collections.newSetFromMap(new IdentityHashMap<>())) to bound traversal against a hand-built cyclic child-suite graph, since TestNG's own parser output is a tree but this method accepts a plain List<XmlSuite>.
