When a host wrapper cannot represent multiline GitHub prose without making the outer tool source ambiguous, create a temporary body file with the approved file-editing path and invoke `gh` with `--body-file`. This is a transport fallback, not a ban on GitHub prose heredocs or here-strings: R23 explicitly permits data-only multiline bodies attached directly to `gh issue|pr create|edit`, while still refusing source-writing heredocs and multiline commit metadata. A blocked wrapped-tool attempt during #4961 and the R23 self-tests prove the distinction.
