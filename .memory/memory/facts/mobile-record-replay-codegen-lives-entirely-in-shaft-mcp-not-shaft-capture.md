shaft-capture (CaptureGenerator/ApiCaptureGenerator) covers web and API surfaces only -- no mobile/Flutter/Appium package exists under shaft-capture. Real mobile record/replay/codegen is implemented in shaft-mcp (McpMobileRecordingService, MobileService, McpMobileCode) behind the unified capture_generate_replay/capture_code_blocks/capture_record_at_target_code_blocks MCP tools (design doc Decision 2 absorbed the former mobile_*/playwright_* codegen twins). It produces copy-paste Java code blocks (replay method, locator inventory, Page Object draft) via McpMobileReplayResult, not a full compiled+validated JUnit test class the way CaptureGenerator/ApiCaptureGenerator do -- there is no compile/validate step and no CaptureGenerationReport for this path. Separately, #4199 (closed) added a real typed FlutterDriverOptions arm in OptionsManager.setDriverOptions (APPIUM_FLUTTER case, shaft-engine/src/main/java/com/shaft/driver/internal/DriverFactory/OptionsManager.java:193) -- driver capability wiring, unrelated to shaft-capture's codegen pipeline.
