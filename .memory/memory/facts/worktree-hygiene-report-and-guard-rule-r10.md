Two harness checks added in PR #4439 (issue #4437), both provider-agnostic.

1. `scripts/ci/worktree_hygiene.py` classifies every worktree as corrupt, abandoned, superseded, uncommitted, unknown, or clean, and `scripts/ci/validate_agent_setup.py` prints one advisory line per finding -- so the signal rides along with the `--skip-external` run AGENTS.md already prescribes. Advisories are reported, NEVER fatal: concurrent sessions legitimately hold dirty worktrees. Run `py -3 scripts/ci/worktree_hygiene.py --check-pull-requests` for the standalone report with the GitHub lookup, which is deliberately not wired into the validator (one network round trip per worktree).

Classification uses `git cherry`, not ahead/behind: the abandoned branches carried commits whose PATCHES were already on origin/main, which ahead/behind reads as live work. Every verdict past 'there are uncommitted files here' needs positive evidence, because the advice is destructive -- a freshly created worktree is clean with no unique patch, identical on paper to one whose work has landed. Left alone: a `locked` worktree (a live session holds it), the primary checkout, the current worktree, one parked on the upstream branch, and one that has never committed. `prunable` entries are skipped; a git query that cannot answer reports `unknown`, never `clean`.

2. Guard rule R10 in `scripts/agents/guard.py` denies `git add`/`git stage`/`git commit` when a candidate file is >=95% NUL across head, middle, and tail samples. Unlike R1-R9 it reads repository state, so it is dispatched with a working directory alongside R9 rather than from the pure `evaluate_command` path, and every uncertain step fails open. It resolves `git -C` / `--work-tree`, covers untracked files, and honours an explicit `git add <path>` pathspec so healthy work can still be committed while a corrupt file sits in the tree. Deliberate limits: wholly zeroed files only (not 84%-NUL partial corruption), no `git` alias resolution, no submodule descent.

Every module `validate_agent_setup.py` imports must also be listed in `AGENT_VALIDATION_SCRIPT_FILES` in `scripts/mcp/install_shaft_mcp.py`, or the installed validator dies on ImportError; a test reads the real import statements.
