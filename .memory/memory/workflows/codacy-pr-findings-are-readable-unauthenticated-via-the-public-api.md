When the Codacy Static Code Analysis check fails on a ShaftHQ/SHAFT_ENGINE PR, the exact findings (pattern id, severity, file:line, message) are available without auth: curl https://app.codacy.com/api/v3/analysis/organizations/gh/ShaftHQ/repositories/SHAFT_ENGINE/pull-requests/<PR>/issues -- parse .data[].commitIssue. Much faster than guessing from the dashboard link. Typical gate: fails on >=1 medium (Warning) severity issue; Info-level CodeStyle alone also flips it when alerts threshold is exceeded. The check titles itself "N new issues (0 max.) of at least medium severity" -- zero tolerance, one medium finding fails the PR regardless of everything else. There is no Codacy config in the repo (no .codacy.yml, no PMD/Checkstyle ruleset); findings are server-side only.

That endpoint returns a DELTA, not a list of open findings: every element carries a sibling `deltaType` of `Added` or `Fixed`, and a Fixed element keeps the finding's ORIGINAL lineNumber, lineText, and commitInfo.sha from before the fix. Counting `.data | length`, or reading the file:line entries, therefore reports a fully-cleared PR as still carrying all of its findings. Always group by deltaType and judge on `Added` only -- verifying PR #4446 (issue #4442) returned 23 elements that were 23 Fixed and 0 Added, while the Codacy check on that same PR was SUCCESS. The stale lineText is the tell: it quotes source the branch no longer contains.

Second, gh-native retrieval path via GitHub's own check-runs annotations API (no separate Codacy auth needed), verbatim and runnable: sha=$(gh pr view <n> --json headRefOid --jq .headRefOid); crid=$(gh api "repos/ShaftHQ/SHAFT_ENGINE/commits/$sha/check-runs?per_page=100" --jq '.check_runs[]|select(.name|test("Codacy"))|.id'); gh api "repos/ShaftHQ/SHAFT_ENGINE/check-runs/$crid/annotations" --jq '.[]|"\(.path):\(.start_line) [\(.annotation_level)] \(.message)"'. Caveat: an empty annotations response while the check-run's own status is still `in_progress` means unfinished, not clean -- read the check-run's `status` field alongside the annotations query before concluding there are no findings. Six PRs went red on this gate on 2026-07-26; each was a one-or-two-line fix once the annotation was in hand.
