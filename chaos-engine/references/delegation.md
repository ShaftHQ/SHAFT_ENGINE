# Delegation

Delegation is optional and distributes work, never responsibility. Select it only when parallel
evidence or a bounded specialist task reduces uncertainty or elapsed time.

## Capability levels

- **Most intelligent:** architecture, high-stakes or hard-to-reverse decisions, and deep challenge.
- **Default:** bounded implementation, debugging, testing, research, and ordinary review.
- **Mechanical:** deterministic, reversible, specification-exact transformation.

Use only these names in tracked guidance. Never bind policy to a vendor, product, or runtime setting.

## Dispatch contract

Give a delegate the outcome, exact scope, known evidence, exclusions, authority, and requested proof.
Independent writers need independent file scopes. The main thread resolves ambiguity, inspects work
before adopting it, and owns synthesis and delivery.

Review is a task the user or risk model may select, not a universal gate. A reviewer is read-only,
confirms the artifact under review, and reports concrete scenario/evidence/path findings. A delegate's
self-report is evidence to inspect, not proof.

Close or release delegates when their assignment ends. Do not create delegation, review rounds,
worktrees, receipts, or waiting loops merely to satisfy process.
